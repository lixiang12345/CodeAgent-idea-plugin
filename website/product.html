Product

为真实工程仓库设计的
项目级编码智能体

CodeAgent 不是「网页聊天框 + 代码高亮」。它是一个 IDE 原生的智能体产品：交互层长在 JetBrains 平台里，上下文来自本地检索引擎，执行力由一套审批制的 IDE 能力网关提供。

Positioning

一句话定位，三个支柱

CodeAgent 是「IDE 原生编码智能体 + 独立部署的 Agent 后端 + 本地 ContextEngine + 审批制 IDE 能力」的组合。三个支柱缺一不可。

IDE 原生能力网关

插件掌握项目访问、编辑器、终端、Diff 与回滚，并对每一次修改执行审批。智能体获得的是「受控的真实能力」，而不是复制粘贴建议。

本地 ContextEngine

开源检索组件在你机器上索引整个仓库：SQLite 存储、文件监听、五类无模型检索。上下文质量决定智能体上限，而这一切都发生在本地。

可部署的 Agent 后端

提示词、模型凭据、流式模型调用与工具编排集中在一个可自部署的后端服务：本地 Docker 一键起，或托管部署配合 OIDC 服务整个团队。

Why CodeAgent

与通用 AI 聊天助手的差别

把代码贴进网页聊天框也能获得建议，但工程化的智能体需要的远不止「一段回答」。

维度通用聊天助手CodeAgent
上下文来源 手工粘贴的片段，窗口有限 本地 ContextEngine 全仓索引，按需检索词法 / 符号 / 路径 / 代码图 / Git 溯源
改代码的方式 给出建议，由你手工搬运 智能体直接读写文件、跑终端，产出走 IntelliJ 原生 Diff 审阅与回滚
信任模型 依赖使用者自觉 只读 Ask 模式、逐工具权限规则、文件与命令审批卡、检查点恢复
数据边界 粘贴什么就上传什么 索引留在本地；仅选定的运行上下文发往你配置的后端；模型凭据不进 IDE

Workflow

按信任级别选择模式

三种模式共享同一套线程、上下文与工具面，差别只在「允许智能体做什么」。

AGENT · 动手执行

把整件事交给它

  • 典型任务：实现功能、修 Bug、补测试、重构
  • 自主规划任务清单，循环调用工具直至完成
  • 文件与命令变更全部经过审批卡
  • 产出集中在 Agent Edits,统一审阅取舍
CHAT · 结对协作

和懂仓库的同事讨论

  • 典型任务：方案设计、代码讲解、评审意见
  • 自动带上检索到的相关文件与符号
  • 可随时附加项目文件与图片作为上下文
  • 讨论成熟后无缝转入 Agent 执行
ASK · 只读分析

面向生产仓库安全提问

  • 典型任务：接手陌生代码、排查线上问题
  • 严格只读：不写文件、不执行命令
  • 适合对变更零容忍的仓库与场景
  • 结论可靠后再切换模式动手
ContextEngine

上下文是智能体的天花板

CodeAgent 复用开源的 ContextEngine 作为检索层，并把它作为 Git 子模块固定版本、随插件一起分发 —— 检索质量可评测、可复现。

检索类型解决什么问题
词法检索精确匹配标识符、字符串与正则模式
符号检索按函数、类、方法等语义单元定位定义与引用
路径检索按目录结构与文件名快速圈定范围
代码图检索沿依赖与调用关系扩展相关上下文
Git 溯源检索结合提交历史找到「谁在何时为何改过这里」
语义检索(可选)显式接入 OpenAI 兼容向量端点后启用，需手动重建索引
  • 默认零模型依赖 —— 前五类检索纯本地计算，不安装、不启动任何本地嵌入或重排模型。
  • 增量同步 —— 初始化后监听项目文件，增改删自动进索引；状态芯片实时反映初始化、同步与监听异常。
  • 多根目录 —— 支持多模块工作区，按根目录管理索引与激活状态。
  • 检索可评测 —— 仓库内置 golden-query 评测基准与基线对比报告，检索质量的变化会被 CI 抓住。
  • MIT 许可 —— ContextEngine 以 MIT 许可证随插件分发，来源与授权透明。
Separation of Concerns

谁拥有什么，一张表说清

清晰的职责边界是安全模型的前提：每一层只持有完成本职所需的最少数据与最少权限。

层拥有的职责持有的数据
IDE 插件(JVM) 项目访问、审批、编辑器动作、终端执行、Diff / 回滚、托管进程、消息队列 OIDC 令牌与 BYOK 密钥(Password Safe)、插件设置
JCEF 前端(Svelte) 面板交互：线程、消息流、审批卡、任务、Git、Image Canvas、Settings 界面状态；JCEF 不可用时自动降级 Swing 界面
本地 Sidecar(Node) ContextEngine 索引、文件监听、五类检索与文本搜索 SQLite 索引 —— 始终留在开发者本机
Agent 后端(可部署) 提示词组装、模型调用与路由、有界工具循环、账户 / 订阅 / 分享 / 通知 模型与集成凭据、会话记录 —— 集中管理，不下发 IDE
Extensibility

可扩展，但有边界

CodeAgent 的扩展机制全部走「声明 + 校验 + 显式授权」路线：能力可以增加，信任模型不被绕过。

  • Rules(规则) —— 仓库级指导always-on 注入，团队约定一次生效。
  • Skills(技能) —— 按任务显式选择的专项能力包，JVM 校验、后端组装。
  • Commands 与 Hooks —— 自定义命令与生命周期钩子，接入真实运行链路。
  • Agent Profiles 与子 Agent —— 同步 / 异步子智能体，支持持久输出、取消、重试与结果回传。
  • MCP 服务器 —— 标准协议扩展工具面，支持 OAuth 元数据发现与动态客户端注册。
  • 声明式 Plugins —— 有界 JSON 清单：来源、版本、完整性、能力授予逐项校验；不加载任何 JVM / Node / Shell 可执行代码。
Data Flow

数据去哪儿，白纸黑字

始终留在本地

源码本体、ContextEngine 的 SQLite 索引、文件监听事件。分析靠检索，不靠上传仓库。

按运行发送

当前 Agent 运行选定的仓库上下文、规则、技能、消息与工具结果，发送到你配置的那个后端。

只在后端

模型 API 密钥、集成凭据、订阅与账户数据。轮换、审计、撤销都在服务端一处完成。

诚实是产品功能。Settings 汇报真实的后端健康、模型与工具发现结果；分享、通知、订阅等云端能力在后端未配置时明确显示「不可用及原因」，任何交互都不会伪装成功。
Deployment

一个人用，或整个团队用

同一个后端镜像，两种形态：个人开发者本地 Docker 即开即用；平台团队托管部署，统一管控模型、账户与额度。

  • 本地模式 —— docker compose 一条命令，服务起在 127.0.0.1:8788，新装插件零配置直连。
  • 托管模式 —— 构建同一份 Dockerfile,配置统一模型网关或多提供商白名单、PostgreSQL 与 OIDC 登录。
  • 账户与订阅 —— OIDC 单点登录；订阅套餐、用量配额与告警阈值由后端真实计数。
  • 协作面 —— 只读会话分享链接(令牌仅存哈希、复制即轮换)、运营通知下发。
  • 会话云端恢复 —— 账户会话可从后端恢复到新机器，本地与云端状态同步。
