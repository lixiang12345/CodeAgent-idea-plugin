使用手册

从零开始安装、配置并用好 CodeAgent。本手册对应插件 v0.7.30;命令与路径均以仓库根目录为基准。

快速开始

四步让 CodeAgent 在你的 IDE 里跑起来。默认走「本地 Docker 后端」路线，不需要任何账号或云服务。

  1. 启动本地 Agent 后端

    在仓库根目录执行一条命令，Docker 会构建并在 http://127.0.0.1:8788 发布服务：

    bash
    docker compose -f backend/compose.yaml up -d --build
  2. 安装插件

    打开 Settings → Plugins → ⚙ → Install Plugin from Disk…，选择 build/distributions/ 下的插件 ZIP,按提示重启 IDE。

  3. 打开 CodeAgent 面板

    菜单 Tools → Show CodeAgent，或快捷键 Ctrl+Alt+I(macOS 为 ⌃+⌘+I)。本地 Docker 后端运行时，无需填写任何 URL 或令牌。

  4. 等索引就绪，发出第一个任务

    ContextEngine 自动初始化项目索引，状态芯片显示进度。选择 Agent 模式，输入例如「为登录接口补一组失败路径测试」，然后在审批卡里看着它动手。

推荐首个任务：用 Ask 模式问「这个仓库的整体结构是什么?」—— 零风险体验检索质量，再逐步升级到 Chat 与 Agent。

安装插件

从 ZIP 安装

  1. 获取插件发行包(CodeAgent-*.zip，构建产物位于 build/distributions/)。
  2. 打开 Settings → Plugins，点击右上角 ⚙ 图标，选择 Install Plugin from Disk…。
  3. 选中 ZIP 文件确认，按提示重启 IDE。

从源码构建

bash
git submodule update --init --recursive
cd frontend && npm ci && cd ..
cd sidecar && npm ci && cd ..
cd backend && npm ci && cd ..
cd vendor/context-engine && npm ci && cd ../..
./gradlew buildPlugin

构建完成后，安装包位于 build/distributions/；也可以用 ./gradlew runIde 直接启动一个带插件的沙箱 IDE。

部署 Agent 后端

后端负责提示词、模型凭据、流式模型调用与工具编排。三种部署形态按需选择：

方式一：本地 Docker(推荐个人使用)

bash
# 先按 backend/.env.example 配好 backend/.env,再从仓库根目录启动
docker compose -f backend/compose.yaml up -d --build

服务发布在 http://127.0.0.1:8788,新安装的插件默认直连该地址，无需登录、无需填 URL。

方式二：开发直跑(不经 Docker)

bash
cd backend && npm start

监听端口为 8787，需要到 Advanced Settings 里覆盖 Backend URL 才会被插件使用。

方式三：托管部署(团队)

用 backend/Dockerfile 构建镜像部署到你的基础设施，并配置以下环境变量(完整说明见 backend/.env.example):

类别变量说明
模型(二选一)MODEL_BASE_URL + MODEL_API_KEY统一模型网关契约
OPENAI_* / GROK_* / ANTHROPIC_*固定多提供商白名单
基础必填DATABASE_URLPostgreSQL 连接串
OIDC_ISSUER / OIDC_CLIENT_ID / OIDC_CLIENT_SECRETOIDC 单点登录
PUBLIC_BASE_URL / SESSION_SIGNING_KEY对外地址与会话签名密钥
可选：分享SHARE_BASE_URL / SHARE_LINK_TTL_SECONDS只读会话分享链接
可选：通知NOTIFICATIONS_JSON运营通知下发
可选：订阅SUBSCRIPTION_PLANS_JSON 等套餐、配额与告警阈值(SUBSCRIPTION_PLAN_CLAIM / SUBSCRIPTION_DEFAULT_PLAN / SUBSCRIPTION_WARN_RATIO)

客户端侧：在 Settings → Services 填入后端 URL,再到 Settings → Account 完成 OIDC 登录。

分享、通知、订阅属于可选云端面：对应变量未配置时，分享请求返回 503 并附原因、通知为空列表、订阅状态为 unknown —— 界面会如实显示，不会伪装可用。

首次运行

  1. 打开面板

    Tools → Show CodeAgent 或 Ctrl+Alt+I(macOS ⌃+⌘+I)。面板出现在 IDE 侧边工具窗口。

  2. 确认后端连接

    本地 Docker 后端运行时自动连通；托管部署则先在 Settings 配 URL 并登录。Settings 显示的是真实健康检查结果，「配置了 URL」不等于「后端在线」。

  3. 等待索引初始化

    ContextEngine 自动建立项目索引，之后持续监听文件变化做增量同步。仓库状态芯片会显示初始化、自动同步或监听失败；点击芯片仅执行刷新或错误重试。

  4. 选择模式，开始对话

    输入框上方可切换 Agent / Chat / Ask。Node.js 会被自动发现；如有多版本环境，可在 Advanced Settings 指定 22.5+ 的可执行文件。

界面导览

面板自上而下由五个区域组成：

  • 顶栏 —— 线程标题、上下文用量、缩放、分享与线程菜单；左侧汉堡按钮打开线程抽屉。
  • 上下文行 —— 当前工作区(多根目录时可切换)、Guidelines 入口与索引同步状态芯片。
  • 消息流 —— 用户消息、流式助手回复、工具卡片(检索 / 读写 / 终端 / Mermaid 等)、审批卡与任务清单。工具卡可展开查看输入输出明细。
  • 变更条 —— 有文件改动时显示「N files changed」，提供 Review / Keep All / Discard All 快捷入口。
  • 输入区 —— 消息输入框、模式切换、模型显示、附件 / 上下文按钮与发送控制；运行中变为停止按钮。

右上角工作区菜单可进入 Tasks、Git 与 Image Canvas 页面；设置齿轮进入完整 Settings 工作区。

三种模式

模式权限适用场景
Agent读 + 写 + 终端(全部经审批)实现功能、修 Bug、补测试、重构 —— 交付一个完整改动
Chat读 + 检索方案讨论、代码讲解、评审建议 —— 与懂仓库的「同事」对话
Ask严格只读理解陌生代码、排查问题 —— 面向生产仓库零风险提问

模式在输入框左下角随时切换，同一线程内可混用：先 Ask 分析，再 Chat 定方案，最后 Agent 执行。运行过程中输入的新消息会进入会话级 FIFO 队列，由 IDE 能力层按顺序派发，不会打断当前回合。

上下文管理

自动检索

每次运行，后端会通过本地 ContextEngine 检索相关代码：词法、符号、路径、代码图与 Git 溯源五类检索默认可用且不需要任何模型。检索到的来源与片段会以工具卡形式展示，可点开验证。

手动附加

  • @ 或「+ Context」 —— 把指定项目文件附加到本条消息。
  • 拖放 / 粘贴 —— 从项目视图拖入文件，或直接粘贴文本与图片；粘贴内容超过 20 KB 提示警告，超过 200 KB 拒绝并报实际大小。
  • Image Canvas —— 从项目内图片目录挑选图片附加到对话。

索引维护

  • 状态芯片显示初始化 / 同步 / 监听异常；点击是刷新或错误重试，不承载其他操作。
  • 需要全量重建时，执行 IDE 命令 CodeAgent: Reindex Context。
  • 想核查索引与同步细节，运行 CodeAgent: Generate Sync Report 生成报告。
语义检索是显式可选项。CodeAgent 不会在本机安装或启动任何嵌入 / 重排模型；仅当你显式配置了运营方或组织托管的 OpenAI 兼容端点、并手动重建索引后，语义检索才会启用。

审批与权限

Agent 的执行力被一套分层防线约束：

  • 审批卡 —— 文件写入与终端命令在执行前弹出内联审批卡，看清内容后批准或跳过；等待审批的运行有明确的状态提示。
  • 逐工具权限规则 —— 在设置中为每个工具配置放行 / 拒绝规则(shell 命令支持输入正则),拒绝规则优先。
  • 模式即边界 —— Ask 模式从能力层面禁止一切修改，而不是靠提示词约定。
  • 随时取消 —— 运行中的回合可即刻停止；失败回合支持重试，并附可复制的 runId 便于排查。

Agent Edits 与回滚

一次运行产生的所有文件改动集中在 Agent Edits 页(变更条的 Review 按钮进入):

  • Diff —— 逐文件打开 IntelliJ 原生 Diff 查看器，体验与人工 Code Review 一致。
  • Undo —— 逐文件撤销智能体的编辑，路径受保护，不误伤你后续的手工修改。
  • Keep all / Discard all —— 一键全部保留或全部丢弃。
  • Checkpoints —— 运行前的文件快照，可从检查点整体恢复。
边界说明：文件工具的编辑均有回滚路径；但终端命令的任意副作用无法安全推断改动集，因此不提供「自动回滚终端副作用」—— 这是刻意的诚实设计，请对高危命令保持审慎审批。

线程管理

  • 线程抽屉 —— 顶栏汉堡按钮打开；支持搜索、新建、切换。
  • 状态一目了然 —— 活动运行、等待审批、失败与未读回复计数直接显示在列表项上，未读计数持久保存。
  • 置顶与删除 —— 常用线程置顶；删除需要确认，防误触。
  • Markdown 导入 / 导出 —— 会话可导出为 Markdown 归档、评审或迁移，也可导入延续。
  • 长会话导航 —— 按请求逐段跳转 + 「跳到最新」浮钮；工具或审批更新到达时不会把你从历史位置拽走，读到最新处才推进本地已读游标。
  • 云端恢复 —— 登录托管后端的账户会话，可用 CodeAgent: Recover Conversations from Backend 恢复到本机。

Tasks · Git · Image Canvas

Tasks(任务)

任务清单随线程持久化：Agent 规划的步骤实时更新完成状态，你也可以手动管理；支持 Markdown 导入 / 导出，并可清理已完成项。

Git

Git 页读取真实的索引与工作树状态：暂存 / 取消暂存、用 JetBrains Diff 查看差异；提交前必须显式确认，不存在「顺手就提交了」。

Image Canvas(图片画布)

从你选定的项目内目录预览有界大小的位图资源，并可把图片附加到当前对话 —— 例如把设计稿交给 Agent 对照实现。

Mermaid

助手输出的 Mermaid 图表直接在面板内渲染，适合让 Agent 用图讲清流程与结构。

Rules 与 Skills

Workspace Guidelines(仓库指导)

仓库根目录的 AGENTS.md 是工作区级指导文件，由后端组装进每次运行的提示词。用 CodeAgent: Edit Workspace Guidelines 快速打开编辑，或点面板上下文行的 Guidelines 入口。

Rules(规则)

在 Settings → Rules & Guidelines 管理的仓库规则始终生效:代码风格、禁区目录、评审要求等团队约定，一次配置，每次运行都被注入。

Skills(技能)

技能是按任务显式选择的能力包(例如「写迁移脚本」「做性能分析」)。由 JVM 侧校验、后端组装；不选不生效，保证提示词可预算。

Memories 与 Commands

Memories 记录跨会话的持久事实；Commands 提供可复用的自定义命令模板 —— 均在 Settings 对应分区管理。

MCP 服务器

在 Settings → MCP Servers 接入 Model Context Protocol 服务器，扩展智能体的工具面：

  • 支持 stdio 与 HTTP 形态，兼容通行的 MCP 配置 JSON 容器格式(含 env / headers 展开与 http 别名),现有配置可直接迁入。
  • 远程服务器支持 OAuth 元数据发现(RFC 9728 / 8414 / OpenID)与 RFC 7591 动态客户端注册；发现失败或不支持 DCR 时报显式错误，不做静默降级。
  • MCP 工具与内置工具一样受审批与权限规则约束。

自带模型密钥(BYOK)

不想让模型流量走后端统一网关?可以自带密钥。通过 Search Actions(Ctrl+Shift+A / ⇧+⌘+A)执行：

Anthropic
CodeAgent: Set / Clear Anthropic API Key (BYOK)
OpenAI
CodeAgent: Set / Clear OpenAI API Key (BYOK)
AWS Bedrock
CodeAgent: Set / Clear AWS Bedrock Credentials (BYOK) —— 含凭据、区域与模型

密钥写入 JetBrains Password Safe，不落插件配置文件；清除动作即刻从 Password Safe 移除。API Keys 设置分区可查看当前生效状态。

托管进程

开发服务器、watch 构建这类长时命令不适合阻塞对话回合。CodeAgent 把它们放进项目级托管进程会话:

  • 智能体可启动、列出、读取输出、写入 stdin、等待与终止进程 —— 各操作独立可审。
  • 进程变更类操作需要审批；保留输出有上限，不会撑爆内存。
  • 项目关闭时，剩余子进程被统一终止，不留孤儿进程。

故障排除

面板提示后端不可用

  • 本地路线：确认容器在跑 —— docker ps 里应有 backend 服务，地址为 http://127.0.0.1:8788。
  • 开发直跑(npm start，端口 8787)时，必须在 Advanced Settings 覆盖 Backend URL。
  • 托管路线：到 Settings → Services 看真实健康检查结论；URL 配置正确但服务不可达时会如实显示离线。

索引不动或监听失败

  • 看仓库状态芯片：显示错误时点击即重试。
  • 仍异常则执行 CodeAgent: Reindex Context 全量重建，并用 Generate Sync Report 查看细节。

找不到 Node.js

Sidecar 需要 Node.js 22.5+。插件会自动探测 node 与常见安装路径；使用 nvm 等多版本管理时，请在 Advanced Settings 手动指定可执行文件路径。

面板显示为简化界面

JCEF 不可用时插件自动降级为 Swing 兜底界面并给出提示；JCEF 以 out-of-process 模式运行时也会有相应警告。核心对话能力保持可用，恢复 JCEF 后重启 IDE 即回到完整界面。

登录状态异常

先 Sign Out 再 Sign In。令牌存于 Password Safe,插件设置只保留过期元数据；清理系统钥匙串中的相应条目等价于彻底登出。

需要提交问题报告

运行 CodeAgent: Export Logs 生成诊断 ZIP(含扩展状态),连同复现步骤与失败回合的 runId 一起提交到 GitHub Issues。

常见问题

我的源码会被上传吗？

不会整仓上传。索引与源码留在本机；每次运行只把选定的仓库上下文、规则、技能、消息与工具结果发送到你配置的后端。后端由你自己部署时，数据不出你的基础设施。

断网还能用吗？

ContextEngine 检索与索引是纯本地能力，不依赖网络；但智能体回合需要可达的 Agent 后端(本地 Docker 后端在离线环境同样可用，只要模型端点可达)。

支持哪些 IDE?

面向 IntelliJ 平台构建，目标覆盖 IDEA、PyCharm、WebStorm、GoLand、CLion、PhpStorm、Rider;兼容性由 JetBrains Plugin Verifier 校验，IDEA 与 PyCharm 已实机验证，其余产品验证进行中。

它会不问我就改代码吗？

不会。文件写入与终端命令都要经过审批卡；Ask 模式更是从能力层禁止修改。你还可以用逐工具权限规则收紧或放宽默认行为(拒绝优先)。

终端命令造成的改动能自动回滚吗？

不能，而且我们明确不这样承诺：任意命令的副作用无法安全推断改动集。文件工具的编辑有完整回滚路径；终端命令请依靠审批把关与版本控制兜底。

模型密钥放在哪里？

默认在后端集中管理，IDE 侧零凭据；选择 BYOK 时，密钥存入 JetBrains Password Safe,可随时清除。
